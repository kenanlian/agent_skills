# Voice and music

Every episode is narrated with Volcengine Doubao bidirectional TTS over a ducked music bed. The voice sets the pace: each beat lasts as long as its line needs, and the scene clock is computed from the synthesized takes.

## Pipeline

```text
audio.json ──► npm run tts ──► raw take ──► trimmed, -21 LUFS take + voice.json ──► clock.ts ──► npm run build ──► <audio> tracks ──► render ──► loudnorm ──► final MP4
(speaker,       (billed once     (raw/)      (audio/voice/, take durations)          (T, captions,   (writes tracks,     (HyperFrames mixes
 lines, bgm)     per line)                                                            audio plan)     data-duration)      voice + bed)
```

| File | Role |
|---|---|
| `src/episodes/<id>/audio.json` | Source: `voice.speaker` (asked of the user every episode), `voice.resourceId`, ordered `lines`, optional `bgm` |
| `src/episodes/<id>/voice.json` | Generated by `npm run tts`: file and duration per line id. Do not edit |
| `src/episodes/<id>/clock.ts` | DOM-free scene clock `T`, `CAPTIONS`, and `AUDIO_PLAN`, all derived from `voice.json` |
| `src/stage/narration.ts` | Shared types, `sequence` (beat layout), `bgmAutomation` (duck lane), `BGM_LEVELS` |
| `audio/voice/raw/` | Raw TTS responses, keyed by text, speaker, resource, and audio settings. Commit them: regenerating is billed |
| `audio/voice/` | Processed takes, keyed by the raw take plus the processing settings; changing the processing never bills |
| `audio/bgm/` | The loudness-normalized bed. Git-ignored, because the music license may not allow redistribution |

## Voice: ask every episode

The user picks the voice before each video. Never reuse the previous episode's speaker or fall back to `VOLC_TTS_SPEAKER` from the env file; that variable only serves `verify.mjs`. `tts.mjs` exits when `voice.speaker` is empty.

1. Ask for the speaker id (`voice_type`, e.g. `zh_female_gaolengyujie_uranus_bigtts`). If the user names a voice instead, ask for its id from the console's voice list. It must belong to the purchased resource: `seed-tts-2.0` takes 2.0 voices only. On a mismatch the session fails and `tts.mjs` prints the server's error; ask the user again rather than switching resource on your own.
2. Audition the first beat line: `npm run tts -- <id> --line <first beat id>`, and give the user the mp3 path. Synthesize the rest only after the voice is confirmed.
3. `npm run tts -- <id>` synthesizes the remaining lines. Unchanged lines are cached by text, speaker, resource, and audio settings, so a re-run bills only edited lines. The command reports billed characters and total voice seconds.

Raw Doubao takes carry about 0.4 s of silence at each end, and their loudness varies by speaker and line (`zh_female_meilinvyou_uranus_bigtts` measured -21.6 to -24.9 LUFS across five lines). `tts.mjs` therefore trims each take to 0.05 s before the first word and 0.1 s after the last (threshold -40 dB; -50 dB left the noise floor in), then applies one static gain to -21 LUFS, capped at a -1.5 dBFS peak. Without the trim, every caption appears 0.4 s before its voice and every beat gains 0.8 s of dead air.

## Lines

```json
{
  "voice": { "speaker": "<asked of the user>", "resourceId": "seed-tts-2.0" },
  "lines": [
    { "id": "intro", "text": "Card Workspace，全文搜索" },
    { "id": "open", "text": "点击工具栏的搜索按钮" },
    { "id": "result", "text": "只留下命中的卡片，并显示命中数", "say": "只留下命中的卡片，并显示命中数量" }
  ],
  "bgm": { "file": "audio/bgm/somewhere-sunny.mp3", "offset": 0 }
}
```

- **Intro line**: the plugin name plus this episode's topic (the `.title`), spoken over the brand card. The outro is not narrated.
- **Beat lines**: one per storyboard beat, in order. `text` is the caption on screen and the spoken text; `main.ts` renders captions from `CAPTIONS`, so the two cannot drift.
- **`say`** overrides the spoken text of one line, only to fix pronunciation (an English term, a number, a polyphone). The caption keeps `text`. Keep the meaning identical.
- Keep a caption to one line (≤ ~24 CJK characters). The verified voice speaks about 4–5 characters per second, so a full-length line is about 5 s.

## Timing from the takes

`clock.ts` places the intro line at 0.3 s and holds the intro card until the line ends plus 0.25 s. The beats then run end to end through `sequence(start, beats, manifest)`:

- A beat lasts `max(min, lead + take + tail)`, with `lead` 0.05 s and `tail` 0.55 s. `min` is the time its choreography needs.
- The caption and the line start together at the beat start. Choreography offsets are relative to the beat start, so the line announces the action and the action lands while it is spoken or just after it.
- A longer line lengthens the hold at the end of its beat; it never moves the beat's own steps. If the hold gets long (over ~1.5 s of stillness), shorten the line or add choreography, rather than slowing the motion.
- The explainer rule is unchanged: it reacts 0.05–0.35 s after the UI step.

The root's `data-duration` is written from `T.end` by the build, so it no longer needs hand syncing.

## Music bed

The series bed is Somewhere Sunny (ver 2) (see "Choosing music" below). Normalize it once per episode length:

```bash
node scripts/loudnorm.mjs "audio/source/Somewhere Sunny (ver 2).mp3" audio/bgm/somewhere-sunny.mp3 --lufs=-21 --from=0 --for=<T.end>
```

Measure only the section the episode plays: a track's whole-file loudness can differ from that section by 1–1.6 LU (Cherry Blossom 10–35 s, Somewhere Sunny (ver 2) and Limit 70 0–25 s), which skews the bed against the voice and makes tracks unfair to compare.

-21 LUFS is the level `tts.mjs` gives every take, so `BGM_LEVELS` read as distance under the voice for any speaker: bed 0.4 between lines, 0.2 under a line (attack 0.2 s before it, release 0.5 s after it, lines closer than 0.8 s stay ducked), 0.75 from the outro, 0.6 s fade-in, 2 s fade-out. These are starting values; tune them on the first reviewed episode and update this file. The build fails if the bed is shorter than `offset + T.end`.

`bgm.offset` starts the episode later in the track. Choose it from the track's short-term loudness, so the episode sits in one steady section rather than a sparse opening or a later, fuller arrangement:

```bash
ffmpeg -hide_banner -nostats -i track.mp3 -af "ebur128=metadata=1,ametadata=print:key=lavfi.r128.S:file=st.txt" -f null -
```

Then take the peak of `lavfi.r128.S` per 5 s window. Example: Cherry Blossom is sparse for 0–10 s (-18 to -19.5 LUFS), steady for 10–35 s (-15.7 to -13.9 LUFS), and much fuller from 45 s on (up to -10.7 LUFS), so a 25 s episode uses `offset: 10`. Somewhere Sunny (ver 2) and Limit 70 are steady from 0 s.

### Choosing music

The bed should feel calm, tidy, and lightly playful, like the flat geometric motion: soft electronic or light pop with plucks, marimba, kalimba, or soft electric piano over light percussion; 100–115 BPM; major key; no vocals; no drops, risers, or heavy low end; sparse in the 1–4 kHz band where the voice sits. Avoid epic cinematic, EDM, the corporate ukulele cliché, and lo-fi crackle that muddies speech. Prefer one track for the whole series so it becomes the brand's sound.

The license must cover commercial use on Bilibili and Xiaohongshu. To replace the series bed, the user either supplies the file and confirms its license or asks you to choose. When asked to choose, shortlist from a library whose license you can state, and have the user listen before committing to it: you cannot judge feel from metadata. Avoid MusicGen output: its model weights are CC-BY-NC.

- Kevin MacLeod's incompetech library is CC BY 4.0 (commercial use; credit required in the video description) and publishes a filterable index with `bpm`, `feel`, `instruments`, and `length` at `https://incompetech.com/music/royalty-free/pieces.json`; tracks download from `https://incompetech.com/music/royalty-free/mp3-royaltyfree/<filename>`. Credit line: `"<Title>" Kevin MacLeod (incompetech.com), Licensed under Creative Commons: By Attribution 4.0 License`.
- Pixabay returns 403 to scripted requests; the user has to download from it.
- **Series bed (chosen by the user after A/B samples, 2026-10-08): Somewhere Sunny (ver 2)** by Kevin MacLeod, 106 BPM, clean guitar duet, 1:55. Not the 0:59 original "Somewhere Sunny". Use it for every Card Workspace episode unless the user asks for another track. Download it from `https://incompetech.com/music/royalty-free/mp3-royaltyfree/Somewhere%20Sunny%20%28ver%202%29.mp3`, start at `offset: 0`, and credit `"Somewhere Sunny (ver 2)" Kevin MacLeod (incompetech.com), Licensed under Creative Commons: By Attribution 4.0 License` in every video description. It holds within about ±1.5 LU from 0 s to ~105 s (-13.9 to -17.8 LUFS short-term) and fades out after 110 s.
- Compared and not chosen: Cherry Blossom (100 BPM, marimbas and shakers; briefly the pick, `offset: 10`) and Limit 70 (103 BPM, electric piano and synths).

## Build and render

`npm run build` bundles `clock.ts` for Node, copies takes to `assets/voice/<line id>.mp3` and the bed to `assets/bgm/`, and writes between `<!-- audio:begin -->` and `<!-- audio:end -->`:

```html
<audio id="vo-open" src="assets/voice/open.mp3" data-start="4.55" data-duration="2.2" data-volume="1"></audio>
<audio id="bgm" src="assets/bgm/somewhere-sunny.mp3" data-start="0" data-duration="25" data-media-start="0"
       data-volume="0.4" data-fade-in="0.6" data-fade-out="2" data-automation='{"version":1,"lanes":[…]}'></audio>
```

The tracks must be static HTML: see [hyperframes.md](hyperframes.md#audio). HyperFrames mixes them during render. Then master the mix (video stream copied, audio re-encoded). `loudnorm.mjs` applies one static gain capped at the true-peak ceiling, never ffmpeg's dynamic loudnorm mode, which compresses the voice and changes how the speaker sounds:

```bash
node scripts/loudnorm.mjs renders/<id>.mp4 renders/<id>.final.mp4 --lufs=-16
```

## Verify

```bash
ffprobe -v error -show_entries stream=codec_type,codec_name,duration -of compact renders/<id>.final.mp4
ffmpeg -hide_banner -nostats -i renders/<id>.final.mp4 -af ebur128=peak=true -f null - 2>&1 | tail -12
```

- One `aac` audio stream as long as the video.
- Integrated loudness about -16 LUFS (up to ~0.5 LU under when the gain is peak-limited), true peak ≤ -1.5 dBTP.
- If the voice sounds unlike the speaker's online sample, compare against the untouched server output in `audio/voice/raw/` before changing the voice: trimming, the static gains, and the mix should not change timbre.
- Listen through once at each caption change: every line starts with its caption, nothing is clipped at a beat boundary, the bed dips under each line and rises for the outro.

Report to the user the speaker id, billed characters for this run, and voice seconds against the demo length.

## Capability: TTS protocol

The purchased account was verified with one sentence: `SessionFinished` billed 9 characters, and the result was a 1.872 s mono MP3 at 24000 Hz / 128 kbps. `templates/scripts/tts.mjs` was also checked end to end: 5 characters billed for a 5-character line, a re-run billed 0, and a five-line episode with `zh_female_meilinvyou_uranus_bigtts` billed 62 characters for 62 characters of text. The standalone check is `node ~/.config/volc-tts/verify.mjs`, which writes `~/.config/volc-tts/verify.mp3`. Official protocol: [双向流式文本转语音 WebSocket](https://docs.volcengine.com/docs/DoubaoVoice/bidirectional-streaming-text-to-speech-websocket?lang=zh).

### Credentials

`~/.config/volc-tts/env`, mode `600`. Keep the key in that file. Do not copy it into the skill, a video project, a prompt, or a commit.

| Variable | Role |
|---|---|
| `VOLC_TTS_API_KEY` | New-console API key. Use this when it is set. |
| `VOLC_TTS_APP_ID`, `VOLC_TTS_ACCESS_KEY` | Legacy console pair. Use only when `VOLC_TTS_API_KEY` is empty. |
| `VOLC_TTS_RESOURCE_ID` | `verify.mjs` only; default `seed-tts-2.0` (语音合成 2.0 字符版). Episodes set `voice.resourceId` in `audio.json`. |
| `VOLC_TTS_SPEAKER` | `verify.mjs` only. Never an episode default. |
| `VOLC_TTS_TEXT` | `verify.mjs` only; optional check line. |

### Call

Endpoint: `wss://openspeech.bytedance.com/api/v3/tts/bidirection`

Handshake headers:

| Header | Value |
|---|---|
| `X-Api-Key` | `VOLC_TTS_API_KEY` |
| `X-Api-App-Id`, `X-Api-Access-Key` | Legacy pair, in place of `X-Api-Key` |
| `X-Api-Resource-Id` | `seed-tts-2.0` |
| `X-Api-Connect-Id` | A new UUID for every connection |
| `X-Control-Require-Usage-Tokens-Return` | `*` so `SessionFinished` includes `usage.text_words` |

One WebSocket connection carries one session and one text payload. Send the whole line in a single `TaskRequest`.

1. `StartConnection` (event 1), payload `{}` → `ConnectionStarted` (50).
2. `StartSession` (100) → `SessionStarted` (150). Speaker and audio settings apply here.
3. `TaskRequest` (200) with `req_params.text` set to the spoken text.
4. `FinishSession` (102), payload `{}`. Collect `TTSResponse` (352) audio until `SessionFinished` (152).
5. `FinishConnection` (2).

`namespace` is `BidirectionalTTS`. A fresh UUID is the session id.

`StartSession` payload:

```json
{
  "user": { "uid": "product-demo-video" },
  "event": 100,
  "namespace": "BidirectionalTTS",
  "req_params": {
    "speaker": "<voice.speaker>",
    "audio_params": { "format": "mp3", "sample_rate": 24000, "bit_rate": 128000 }
  }
}
```

`TaskRequest` payload:

```json
{
  "event": 200,
  "namespace": "BidirectionalTTS",
  "req_params": { "text": "这是一段配音测试。" }
}
```

Set `bit_rate` on MP3. The service default is low enough to dull the voice.

### Binary frames

Integers are big-endian. A client text frame is a 4-byte header, an `int32` event, then a sized JSON payload.

| Byte | Value | Meaning |
|---|---|---|
| 0 | `0x11` | Protocol v1, 4-byte header |
| 1 | `0x14` | Full client request, event number present |
| 2 | `0x10` | JSON, no compression |
| 3 | `0x00` | Reserved |

Connection events `1`, `2`, `50`, `51`, and `52` omit the session id. Every other event writes `uint32` session-id length, the id, then `uint32` payload length and the payload. `ConnectionStarted`, `ConnectionFailed`, and `ConnectionFinished` insert a connect-id length and id before the payload.

Server audio uses header byte 1 = `0xB4` (audio-only, with event), raw bytes, event `352`. An error frame uses header byte 1 = `0xF0`, then a `uint32` error code and a sized payload, and has no event number.

### Acceptance per take

- `ConnectionStarted`, then `SessionStarted`, then one or more `TTSResponse` chunks, then `SessionFinished`.
- `usage.text_words` equal to the Unicode length of the spoken text, including punctuation (`tts.mjs` warns otherwise).
- An MP3 that starts with `ID3` or `0xFF` and is longer than a few hundred bytes.
